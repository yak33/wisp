## M4 · 备忘快贴 — 2026/08/16

标签化的文本片段库。粘贴链路直接复用 M2，因此这一版的工作量集中在数据模型与视图层次。

**core**

- [x] 片段 / 标签 / 关联三张表，标签多对多，外键级联删除
- [x] 标签串用 `group_concat` 在 SQL 内聚合，避免逐条回查的 N+1
- [x] 保存与删除走事务，并自动清理不再被引用的孤立标签
- [x] 筛选维度：全部 / 无标签 / 指定标签；关键字同时匹配内容与备注
- [x] 标签解析：中英文逗号、顿号、空白均可分隔，去重且保序
- [x] 表驱动测试 4 例（标签筛选、无标签筛选、备注检索、孤立标签清理）

**app**

- [x] 新增根视图 `WispView`，标签页在剪贴板与备忘之间切换（Ctrl+1 / Ctrl+2）
- [x] 列表态 / 编辑态双形态共用一个视图；编辑态 Ctrl+S 保存、Esc 取消
- [x] 左侧标签侧栏带计数；在某标签下新建时自动预填该标签
- [x] ↑↓ 选择、回车直达粘贴、Ctrl+N 新建、Ctrl+E 编辑

**重构**：窗口级关注点（唤起聚焦、失焦隐藏、标签切换）从 `ClipboardView` 上移到 `WispView` 统一收口——两个子视图并存后，各自监听窗口激活会互相抢焦点。

## M2 · 回车直达粘贴 — 2026/08/15

选中条目后直接落到用户原来所在的输入框，不再需要手动 Ctrl+V。这条链路同时是备忘快贴（M4）的地基。

- [x] 唤起前记录前台窗口（`GetForegroundWindow`），并排除 Wisp 自身
- [x] 交付链路：写剪贴板 → 隐藏窗口 → `SetForegroundWindow` 还原焦点 → 模拟 Ctrl+V
- [x] 粘贴前抬起残留的物理修饰键（Alt/Shift/Win），避免 `Ctrl+V` 被污染成组合键
- [x] 全程在独立线程执行（80ms 焦点落定 + 20ms 击键间隔），UI 线程零阻塞
- [x] 目标窗口失效时静默降级为"仅复制"，内容仍在剪贴板
- [x] `Enter` 直达粘贴，`Ctrl+Enter` 仅回填剪贴板

**设计要点**：记录时机是全链路的关键——必须在 Wisp 抢到前台**之前**捕获，否则记到的是自己。

## M1 · 剪贴板历史（文本）— 2026/08/15

首个可用版本，从零到常驻运行。

**core 层（wisp-core）**

- [x] Win32 message-only 窗口 + `WM_CLIPBOARDUPDATE` 事件驱动监听（零轮询，后台 CPU 0%）
- [x] SQLite 存储：WAL 模式、FNV-1a 指纹去重（哈希命中后仍比对原文，碰撞零误判）
- [x] 重复内容置顶而非重复入库（含自我复制回环，即"从 Wisp 复制"也会置顶该条）
- [x] 模糊检索：LIKE 通配符按字面转义；置顶项恒排最前；上限 500 条
- [x] 超大文本熔断（>2MB 不入库）；剪贴板占用时短退避重试读取
- [x] 表驱动测试 3 例全绿（去重置顶 / 通配符转义 / 置顶排序）

**app 层（wisp-app）**

- [x] 无边框客户端装饰窗口，预创建 + `ShowWindow` 显隐（唤起体感零延迟）
- [x] 全局快捷键降级链：`Alt+Space` → `Ctrl+Alt+Space` → ``Alt+` ``（实际生效键显示于状态栏与托盘）
- [x] 托盘：双击唤起、右键菜单退出
- [x] 唤起即聚焦搜索框；窗口激活自动补查（隐藏期间错过的变更不丢）
- [x] ↑↓ 键盘导航 + 回车/点击复制并隐藏 + Ctrl+P 置顶 + Esc/失焦隐藏
- [x] 虚拟列表渲染，数据量与帧率无关

**实测**：常驻内存 ~27MB（debug 构建）。

**踩坑记录**

1. windows crate 0.58 与 0.61 的参数风格不同（`Param<T>` vs `Option<T>`），统一升至 0.61；
2. `RegisterClassW` 被 `Win32_Graphics_Gdi` feature 门控（WNDCLASSW 含 GDI 类型），workspace 构建时被依赖树的 feature 联合掩盖，单测 `-p wisp-core` 才暴露——workspace 显式补齐该 feature；
3. Rust 2024 的 RPIT 默认捕获入参生命周期，返回元素的辅助函数需返回具体类型（如 `Div`）而非 `impl IntoElement`。

## M0 · 技术选型与 PoC — 2026/08/15

**结论：GPUI + gpui-component 路线成立。**

| 验证项 | 结果 |
|--------|------|
| gpui + gpui-component 在 Windows 11 / Rust 1.97 构建 | ✅ 一次通过 |
| 中文 IME（候选框跟随、上屏） | ✅ 用户实测通过 |
| 5 万条虚拟列表滚动 + 即时过滤 | ✅ 流畅（用户评价"比 uTools 还丝滑"） |
| 托盘 + 全局快捷键与 gpui 事件循环共存 | ✅ 通过 |
| 窗口隐藏 / 唤醒 / 失焦隐藏 / 唤起即聚焦 | ✅ 通过 |
| 无边框窗口客户端装饰（圆角 / 边框） | ✅ 通过 |
| PoC 常驻内存（含 5 万条 mock 数据，debug） | 47MB |

**关键决策与依据**

- **不选 Tauri**：本场景性能体感两者无差（虚拟列表 / 窗口显隐均不卡在 UI 框架），选 GPUI 的真实动机是原生单进程 + 学习价值；gpui-component（60+ 组件，LongPort 生产验证）把组件成本降到可接受。
- **core 与壳解耦**：`wisp-core` 零 UI 依赖，选型风险被隔离在壳层，未来可随时换壳。
- **gpui 依赖策略**：gpui-component 锁 rev（`be6f5a7`），gpui 跟随其要求从 Zed 主干解析，由 `Cargo.lock` 固定。

**遗留技术债**

- [ ] 事件泵为 50ms 轮询（托盘/快捷键/变更信号），待换 `set_event_handler` + 主线程投递
- [ ] 进程退出时托盘图标偶发残留至鼠标划过（Windows 常见现象，低优先级）
